## 🚀 VIRAL COEFFICIENT ANALYSIS

### What is Viral Coefficient?

```
VIRAL COEFFICIENT (k):
k = (invites per user) × (conversion rate of invites)

If k > 1: Exponential growth (each user brings >1 new user)
If k < 1: Linear growth (need other channels)
```

---

### Your Referral Program Potential

**Pessimistic (k = 0.3)**:
```
Assumptions:
├─ 30% of users send 1 invite
├─ 30% of invites sign up
└─ k = 0.30 × 1 × 0.30 = 0.09

Result: Every 100 users → 9 referred signups
```

**Realistic (k = 0.5)**:
```
Assumptions:
├─ 50% of users send 1 invite
├─ 40% of invites sign up (25% discount is compelling)
└─ k = 0.50 × 1 × 0.40 = 0.20

Result: Every 100 users → 20 referred signups
```

**Optimistic (k = 0.8)**:
```
Assumptions:
├─ 60% of users send 2 invites (tiered rewards)
├─ 40% of invites sign up
└─ k = 0.60 × 2 × 0.40 = 0.48

Result: Every 100 users → 48 referred signups (nearly 50%!)
```

## 🎯 FRAUD PREVENTION FOR REFERRALS

### Potential Abuse Cases

```
SCENARIO 1: Self-Referral
├─ User creates fake account
├─ Refers themselves
├─ Gets 25% off + referrer credits
└─ COST: You pay both discounts

SCENARIO 2: Referral Farming
├─ User creates 10 fake emails
├─ Refers all of them
├─ Gets 10× referrer rewards (500 credits)
└─ COST: Wasted credits on fake accounts

SCENARIO 3: Family/Friend Circle
├─ 5 friends all refer each other
├─ All get 25% off + 4× referrer bonuses each
└─ COST: Legitimate but high discount rate
```

---

### Anti-Fraud Measures (Use Existing System)

```
LEVERAGE YOUR FRAUD PREVENTION:
├─ Email normalization (block Gmail +tricks)
├─ Device fingerprinting (max 2 accounts per device)
├─ IP rate limiting (max 3 signups per IP)
├─ Payment verification (must actually purchase)
└─ Behavioral analysis (fake accounts don't engage)

REFERRAL-SPECIFIC RULES:
├─ Referrer only gets reward AFTER friend purchases
│   └─ Prevents fake signup farming
├─ Max 10 referrals per month (prevents mass abuse)
├─ Must verify email to use referral code
└─ Can't refer yourself (match payment methods)
```
