# L5 Input-Depth + Surfacing Wiring — Implementation Plan

> **Status:** Step 1 in progress. Authoritative plan for bringing the actionable
> coaching layer (L5 essay-level rewrites) to production and raising its input
> ceiling to the gold-standard reference-review insight level.
> **Created:** 2026-06-03.

---

## Problem

The actionable, student-facing coaching the system is *supposed* to produce —
"here's your signature move, here's where you abandoned it, here's a target" —
is generated by the **L5 essay-level rewrite layer** (`rewriteGeneration.ts`,
`generateEssayLevelRewrites`), which emits `L5GrowthAnnotation` (multi-draft
rewrites), `L5PreservationAnnotation` (protect-this), and `L5ReframeAnnotation`
(the transformative reframe).

Two facts established by investigation:

1. **The layer is dormant.** `generateEssayLevelRewrites` has **zero orchestrator
   call sites** (gated by flag `L5_ESSAY_LEVEL_REWRITES`; build items 8 validators
   + 9 wiring deferred — see the file header). It ran once standalone (2026-05-30,
   `tests/output/l5-essay-level-crochet-VERIFY.json`) and already produces
   near-bar coaching. The student doc (`renderAnalysisForStudent.ts`, deterministic,
   no LLM) surfaces **none** of its growth/preservation/reframe annotations.

2. **Its ceiling is its inputs.** The surfaces we spent a session hand-polishing
   (Signature Move, Protected Strengths, etc.) are *diagnostic inputs* to L5, not
   student output. Polishing their voice is low-value; deepening their *analysis*
   is the ceiling on everything downstream.

### Audit finding (vs. the gold standard)

Benchmarked every L5 input against the reference review
`tests/calibration/top-tier-reference/reviews/14-clara-crochet-review-v2.md`
(v2.1 close-reading methodology). Result:

- **Already match/exceed the reference:** `imageSystem`, `transformativeInsight`,
  `coachingMap.priorities`, `protectedStrengths`, `throughLineMap`,
  `structuralRoles`, `redFlags`, `writerPortrait`, `blindSpots`,
  Moment Earnedness Map, and `signatureMove` *when it runs*.
- **Below the reference (the work):** `distinctivePatterns`, `sentencePatterns`,
  `voiceIdentity.signature`, `vocabularyDomains`, `sentenceRhythm.baseline`,
  `tonalDisposition`, `intellectualFingerprint`, `institutionalFit`,
  `portfolioPosition`, `memorability`.

**The single systemic pattern:** below-bar fields **label and locate** a feature
where the reference **decodes the mechanism** ("the denial is responsive to actual
inference, not a straw-man") and **discriminates** (names *the* memory anchor;
says where the essay fits *worse* and why). The reliably-deep fields all share
one trait: a **forced-structure prompt** (redFlags' mandatory checklist). The
below-bar fields are open-ended "describe X" prompts the model satisfies with a
competent inventory.

**Plus a capability gap:** no input does **cultural/domain decoding** (the
reference reads "patience, decorum, poise" as Confucian female-virtue vocabulary;
chrysanthemums as Vietnamese funerary flowers).

**Plus three structural bugs (verified at HEAD):**
1. `signatureMove` silently nulls — `intraDomainValidation.ts`
   (`validateSignatureMoveAgainstParagraphs`) returns `null` for the **entire**
   move on **any single** instance failure (one off-by-one P-index or smart-quote
   drift). The dump then asserts the flattering "craft distributed across multiple
   strengths" — on an essay that is the prompt's *own worked example*.
2. `strengthSignatures` bloated/duplicated — two sources merged with exact-string
   dedup only; per-paragraph verdict prose + growth-edge leakage accumulate (~21
   mixed entries). L5 can't tell what actually works.
3. Per-sentence L3.5 analysis is **not rendered** in the dump (it *is* persisted
   and consumed — `essayProfileManager.ts:2300`, `analysisPass.ts:315`,
   `profileTypes.ts:787` — so this is a dumper gap, not data loss).

## Goal

- **Step 1 (this plan's focus):** raise the below-bar inputs to the reference
  insight level + fix the 3 bugs + add cultural decode. Verify on crochet + #02.
- **Step 2:** wire + surface the L5 layer end-to-end.
- **Step 3:** calibrate L5 output to the locked Signature-Move / Protected-Strengths
  shapes from the design session.

## Step 1 — Deepen the inputs

### 1A. Fix the three structural bugs

- **signatureMove null collapse** — `intraDomainValidation.ts:446-525`,
  `holisticSynthesis.ts` `synthesizeSignatureMove` (~:2960), and the renderer of
  the "distributed across multiple strengths" copy.
  - Drop only the **offending instance**; keep the move if **≥3 valid instances**
    remain (the move's cardinality bar).
  - Emit distinct telemetry: `llm_returned_null` vs `validator_rejected_n` vs
    `parse_error` — a rejection must never masquerade as an honest "distributed
    craft" verdict.
  - Gate the "distributed across multiple strengths" student copy on a **genuine
    LLM null**, not a downstream-nulled value.
  - *Functional capability fix:* restores a flagship L5 input currently pinned at zero.
- **strengthSignatures bloat** — `analysisPass.ts:~2396-2416`,
  `holisticMutator.ts:~180-192`.
  - Stop routing per-paragraph `primaryStrength`/`reasoning` into
    `strengthSignatures` (it belongs in a paragraph-verdict field), **or** dedup by
    `(normalized quality + sorted paragraphs)` and cap evidence to a short quote.
- **Per-sentence render gap** — add per-sentence L3.5 fields to the dumper
  (`tests/dump-full-profile.ts` or equivalent) so the finest-grained judgment is
  auditable against the reference's sentence-level depth. *Render-only; enables 1D.*

### 1B. Re-prompt the below-bar fields — force mechanism + discrimination

Change **only** these fields; leave the already-deep fields untouched.

| Field | Producing | Forcing question to add |
|---|---|---|
| `distinctivePatterns` | `holisticSynthesis.ts:361` | per pattern: what does this let the writer *get away with* / what does it reveal they trust the reader to do |
| `sentencePatterns` | `:633` | per pattern: what it BUYS and COSTS; the one sentence whose rhythm betrays intent; **ban** "creates variety/momentum" |
| `voiceIdentity.signature` | `:359` | the ONE thing this voice can do a generic strong essayist can't + the register it can't inhabit without strain (cite where it cracks); enforce the `:329` banned-jargon list as a hard self-check |
| `vocabularyDomains` | `:386` | per domain pairing: the collision/tension — which two share a paragraph/sentence and what the writer gains by colliding them |
| `sentenceRhythm.baseline` | `:395` | **forbid** "varied/mixed"; name the DEFAULT sentence shape + the specific event that breaks it |
| `tonalDisposition` | `:405` | free-text quality + `dominates_when`/`yields_when`; one `primaryTone` with the rest subordinated (drop closed enum — LLM-first) |
| `intellectualFingerprint` | `:606` | the writer's DEFAULT meaning-making move (inward / borrowed-frames / system / concrete / people) + cite where it fires; **ban** "thinks through…/comfortable with…/moves between…" |
| `institutionalFit` | `:640` | force a CONTRAST — stronger-for vs weaker-for + why; **ban** "institutions that value [theme]" |
| `portfolioPosition` | `:643` | what THIS essay proves the rest of the app structurally can't + the one adjacent quality it conspicuously fails to evidence; **ban** "occupies the [theme] dimension" |
| `memorability` | `:642` | name THE one element that survives 50 essays, then 1-2 runners-up |
| `authenticityAssessment` | `:458` | split: ≤40-word headline + required `registerHonestyMap` (felt vs performed per register; name ≥1 stated-emotion substitute, e.g. "I am proud") so the load-bearing insight can't be squeezed out by the word cap |

Design constraint: every change forces a **single discriminating claim**, never a
longer inventory. Follow the LLM-first rules (no closed taxonomies, no deterministic
formulas for contextual judgment, soft guidance over hard blocklists where possible).

### 1C. Add cultural/domain decode (new capability)

Add a forced question to **`thematicArchitecture`** (`:564`) and
**`characterRevelation`** (`:597-606`):

> "Decode any culturally-specific or domain-specific language — what does it encode
> that a generic reader would miss (virtue vocabulary, ritual objects, insider
> terms, era-specific framing)? Cite the phrase. If none is present, say none."

Evidence-grounded, LLM-first; feeds every downstream surface.

### 1D. Verify

Re-run **crochet + #02** full profile; diff the targeted fields against
`14-clara-crochet-review-v2.md` and `02-shotaro-building-a-universe-review-v2.md`.
Confirm SURFACE→DEEP and that the already-deep fields didn't regress.
**Cost:** ~2 × $1.20 ≈ $2.40 (within the $5 cap; get explicit go-ahead before the run).

## Risks & guardrails

- **Regression on deep fields:** touch only the flagged below-bar fields; never
  re-prompt `imageSystem`, `transformativeInsight`, `priorities`, MEM, `redFlags`.
- **signatureMove grounding:** keep the per-instance substring/range check — only
  change *all-or-nothing* to *drop-offending-instance*. Do not accept ungrounded
  instances.
- **Cost:** $5 hard cap per run; no tangent dumps/pre-smokes without separate approval.
- **No degraded fallbacks:** if a deepened field fails, return a clear error / null
  with telemetry — never a hardcoded stand-in.
